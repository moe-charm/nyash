Phase12.7-B: tokenizer+config+docs (basic sugar)

Goal: Minimal, reversible basic sugar support pre–self-hosting. Add tokenizer ops and wire sugar_level config; doc the behavior.

Scope:
1) Tokenizer (src/tokenizer.rs)
   - Add 2-char-priority tokens: '?.', '??', '|>', '+=', '-=', '*=', '/=', '..'.
   - Ensure longest-match for sequences (e.g., '??' before '?', '?.' before '.').
   - Add TokenType variants and unit tests covering each.
   - Keep '//' line comments intact; do not add '//' binop sugar here.

2) Syntax config (NYASH_SYNTAX_SUGAR_LEVEL and nyash.toml)
   - Provide SugarLevel enum: none|basic|full and SugarConfig struct.
   - Load order: env var NYASH_SYNTAX_SUGAR_LEVEL overrides nyash.toml [syntax].
   - Implement reader in a new module (e.g., src/syntax/sugar_config.rs) and expose via crate::syntax::SugarConfig.
   - Minimal nyash.toml support: [syntax] sugar_level = "none|basic|full"; default none.
   - Thread through parser entry points later; for now compile-only with a public accessor.

3) Docs (docs/development/roadmap/phases/phase-12.7/README.md)
   - Add note that basic tokenizer + config landed; parser desugar is in-progress.
   - Clarify pipeline resolution policy draft (lhs |> f(a,b) => f(lhs,a,b); lhs |> obj.m(a) => obj.m(lhs,a)).

Constraints:
- No behavior change unless NYASH_SYNTAX_SUGAR_LEVEL=basic or full is set in the future; this patch only adds tokens and config (non-breaking).
- Keep changes minimal and compile green; add small tokenizer tests in src/tokenizer.rs.

Acceptance:
- cargo build --release --features cranelift-jit passes.
- tokenizer unit tests for new tokens pass.
- SugarConfig::from_env_or_toml("nyash.toml") returns expected levels when env set/unset.
